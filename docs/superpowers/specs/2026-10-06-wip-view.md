# Agents plugin: WIP view (`getWipFlags`, `applyWipFix`, in-Kanboard page)

Status: approved design, 2026-10-06. Source: Kanboard map #4879 "Agents plugin WIP view: getWipFlags
API + in-Kanboard page" (project 94) and its closed tickets #4880–#4886. The flag catalogue contract is
Kanboard #4572 (resolution 2058, amendments 2066, 2071, 2088, 2095) on parent map #4563.

## Why

The `kanboard:wip` skill builds the WIP digest by sweeping the API: **575 JSON-RPC calls and about 3 min**
across 18 projects. A plugin with DB access computes the same flags in **four flat queries (~8 ms at hosted
scale, ~62 ms at 10×)** (Kanboard #4881). Exposing them as `getWipFlags` lets the skill become a thin
client later. The in-Kanboard page is the only rendered human surface for this data. Carmelo ruled out
claude.ai artifacts for board data (#4572 amendment 2066).

## Decisions

| # | Area | Decision | Ticket |
|---|---|---|---|
| 1 | Home | Inside the **Agents** plugin, alongside the roster that already knows who is an agent. | map #4879 |
| 2 | Surface | Pull only. No push, notification or scheduled digest from the plugin. The skill answers in chat when invoked. | #4572 / 2066 |
| 3 | Registration | `withObject(new AgentsWipProcedure($this->container))` in `initialize()`. The class extends `BaseProcedure` and has a **prefixed** short name, because ACL maps key on short class names. Core wins name clashes. | #4880 |
| 4 | Project scoping | Core does none for plugin methods. Build it from `getActiveProjectIds($uid)` and `getUserRole($pid, $uid)`. If the resolved project set is empty, **return early**: PicoDb `in('project_id', [])` drops the condition and returns every task. | #4880, #4881 |
| 5 | Errors | Never throw for authorization. Refusals go in `denied:{user_ids, project_ids}`, because one `AccessDeniedException` turns a whole JSON-RPC batch into a 403. Declare procedure params without PHP type hints (a `TypeError` is a fatal with no JSON-RPC body) and validate them inside. | #4880 |
| 6 | Who is an agent | Only the `agents` roster (owner_user_id → agent_user_id). Agents gains an **admin-only adopt action** (UI + `adoptAgent` RPC) that registers an existing user as an agent of an owner. carmelo.claude (10), carmelo.codex (12) and coqui (9) are adopted under carmelo (2) at rollout. | #4882 |
| 7 | Whose work | The view is the viewer's own tickets plus tickets owned by the viewer's Roster agents. Alt accounts are not folded in. | #4882 |
| 8 | Human tickets | Only the Position flags apply (Stale, All subtasks done, Closed not in Done, Worked not claimed, Blocked), with the same thresholds. The Location and time flags are agent-only. | #4882 |
| 9 | No owner | Unowned In-progress tickets count only on projects where one of the viewer's agents is a member. | #4882 |
| 10 | Agent caller | Resolves to its roster owner's view, intersected with the **calling agent's own** project visibility. | #4882 |
| 11 | App token | `getId()=0`, `isAdmin()=false`, so it needs an explicit branch. `getWipFlags` is allowed, sees all projects, and **requires** `owner_user_id`. `applyWipFix` and `adoptAgent` refuse it, because writes must be attributed. | #4882, #4885 |
| 12 | Other users' views | App-admins may view any user. Project managers may view other users only on projects they manage. Anything else is empty plus `denied`. | #4882 |
| 13 | Params | `owner_user_id`, `scope` = `agents`\|`mine`\|`all` (default `all`; the skill passes `agents`), `project_ids`, `include_unflagged` (default false), `closed_lookback_days` (default 30). No threshold overrides. | #4882, #4883 |
| 14 | Disabled agents | Their open tickets stay in, with an `owner_disabled` row marker (fix: Assign). This is a marker, not a catalogue flag. | #4882 |
| 15 | Response | An envelope with summary, ranked rows, `unavailable_flags` and `denied`. Rows carry facts and flag keys, never prose. | #4883 |
| 16 | Ranking | Server-side. A row's rank is its **highest** flag weight; ties go to the oldest last activity. The row's `fix` is the top flag's action. | #4883 |
| 17 | Catalogue home | `catalogue.json` in this repo is canonical. `catalogue_version` = sha256 of the file. The skill vendors a hash-checked copy, and on a mismatch it trusts the server and prints a drift warning. #4572's comments become history that points here. | #4883 |
| 18 | Unavailable flags | Flags whose data doesn't exist yet carry `requires`. Their summary counts are **null**, and they are listed in `unavailable_flags`. | #4883 |
| 19 | One-click | v1: **Move to Done** (Closed not in Done; All subtasks done) and **Assign** (No owner). Every other fix links to `/task/<id>`. | #4885 |
| 20 | Write path | The page controller (CSRF) and `applyWipFix` RPC share one `WipFixService`. `getWipFlags` stays read-only. | #4885 |
| 21 | Fix guards | Recompute the flag for that ticket, and refuse if it no longer holds or `date_modification ≠ expected`. Never Move to Done a ticket tagged `hold` or `wayfinder:*`. An agent caller may fix only agent-owned or unowned tickets. | #4885 |
| 22 | Fix semantics | Closed not in Done → move to Done, keep it closed. All subtasks done → move to Done **and** close. Assign → the viewer or one of their Roster agents who is a member of that project. Each fix posts the comment `🧭 WIP view: <action> (<flag>) by <user>`; move provenance (#4637) records the move. | #4885 |
| 23 | Page layout | Summary chips over the ranked queue (A) by default. A toggle (`?view=owners`) regroups the same rows into one column per owner (C). The BigBoard-style project wall was rejected. | #4886 |
| 24 | Page details | Row fields as prototyped. A "show unflagged" checkbox, remembered in browser storage. Manual refresh. Below 700 px the owner/Location column folds away. Colours are theme-neutral. | #4886 |
| 25 | Entry points | The avatar dropdown (next to My Agents), a dashboard sidebar entry, and a header badge showing the flagged count. | #4886 |

## The catalogue (`catalogue.json`)

Shared verbatim by the plugin and the `kanboard:wip` skill:

| key | Label | Rule | Weight | Fix action | One-click | requires | Applies to |
|---|---|---|---|---|---|---|---|
| `stale` | Stale | In progress, and the latest of `date_moved`, `date_modification` and the newest `comments.date_creation` (excluding bodies starting `⏱ reconciler`) is ≥ **3 days** old | 5 | Message session or park | no | none (its "no live session" refinement uses Location when present) | all |
| `merged` | Merged PR, still open | Location PR state is `merged` and the ticket is not Done | 5 | Move to Done | no | `pr_state` | agents |
| `donesubs` | All subtasks done | Open, every subtask is Done (excluding titles starting `⏱ carried`), not tagged `hold` | 4 | Move to Done | **yes** | none | all |
| `offboard` | Worked, not claimed | In Ready with subtasks Done or In progress (excluding `⏱ carried`) | 4 | Claim it | no | none | all |
| `ended` | Session ended | Location state `ended`, ticket still In progress | 4 | Resume or re-claim | no | `location` | agents |
| `mismatch` | Closed, not in Done | Closed in the last `closed_lookback_days`, outside the Done column, no `wayfinder:*` tag | 3 | Move to Done | **yes** | none | all |
| `blocked` | Blocked | Tagged `blocked` or `needs-info`. Ranked by when `blocked_on` metadata last changed, falling back to `date_modification` | 2 | Answer the question | no | none | all |
| `unverified` | Unverified | Location on another host with `last_seen` > **24 h** | 2 | Check that host | no | `location` | agents |
| `noowner` | No owner | In progress, `owner_id = 0`, on a project where one of the viewer's agents is a member | 1 | Assign | **yes** | none | unowned |
| `timemiss` | Time missing | Done or session ended > **24 h** ago with no Clocked time | 1 | Install back-fill | no | `backfill` | agents |

File shape: `{"version": 1, "thresholds": {"stale_days": 3, "unverified_hours": 24, "timemiss_hours": 24,
"closed_lookback_days": 30}, "flags": [{"key", "label", "weight", "fix", "oneclick", "requires", "applies_to"}]}`.
The rules themselves live in `WipFlagRules` (PHP). The JSON carries every number and label they read.

## `getWipFlags` response

```json
{
  "catalogue_version": "sha256:…",
  "generated_at": 1791300000,
  "viewer": {"user_id": 2, "resolved_from": 10},
  "scope": "all",
  "summary": {"in_progress": 25, "stale": 18, "donesubs": 8, "mismatch": 34, "merged": null, "...": 0},
  "unavailable_flags": ["merged", "ended", "unverified", "timemiss"],
  "rows": [{
    "task_id": 2259, "title": "…", "project_id": 61, "project": "…", "column": "In progress", "is_active": 1,
    "owner_id": 0, "owner_kind": "none", "owner_disabled": false,
    "flags": ["stale", "noowner"], "rank_weight": 5,
    "fix": {"action": "stale", "oneclick": false, "url": "/task/2259", "location": null},
    "evidence": {"date_moved": 0, "last_activity": 0, "subtasks_done": 2, "subtasks_total": 3,
                 "blocked_since": null, "moved_by_kind": "human", "location": null}
  }],
  "denied": {"user_ids": [], "project_ids": []}
}
```

`owner_kind` ∈ `agent|human|none`. `location` is `{state, host, session_id, socket, transcript}`, read from
Location metadata when present (key names come from the Location build, Kanboard #4570).

## `applyWipFix`

`applyWipFix(task_id, action, expected_date_modification, assignee_id = null)` →
`{ok: true, task_id, action, comment_id}` or `{ok: false, reason: "changed"|"not_flagged"|"forbidden"|"hold"|"invalid_assignee"}`.
`action` ∈ `move_to_done`|`assign`. Every guard in Decisions 21–22 runs here; the page POST calls the same service.

## Non-goals

- Rewiring `kanboard:wip` onto `getWipFlags`. That's a skill-side follow-up.
- Changing the catalogue's rules (owned by Kanboard #4572 history; edits now land in `catalogue.json`).
- One-click for Claim, Park, Answer or message-session.
- Any push, notification or digest; caching or polling.
- An MCP wrapper for `getWipFlags`.
- Building Location, the time back-fill or the `pr_state` writer. Their flags stay `unavailable` until those exist.
